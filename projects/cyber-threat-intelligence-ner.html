NLP / Security · Korea University · with Samsung SDS

Cyber Threat Intelligence NER

Korea University · Oct 2020 – Dec 2021

Overview

Security analysts drown in unstructured threat reporting. This project, done with Samsung SDS, aimed to extract structured threat entities (IOCs like hashes, IPs, and CVEs, plus threat actors, malware, and mitigations) automatically from that flood of text.

I built 30+ crawlers to pull 50,000+ security articles into MySQL, constructed a BIO-tagged domain-specific dictionary from scratch, and fine-tuned a PyTorch BERT-NER model, pushing weighted F1 from 65% to 91% after a round of cleaning up mislabeled training data.

Goal: regex extraction wasn't enough

From fixed regex patterns per IOC type to a model that recognizes entities in context

The starting point was pattern matching: a regular expression per IOC type (filename, hash, CVE, URL, IPv4). That catches well-formed indicators but misses everything regex can't express, like which adversary group, country, or industry a report is actually describing. The goal was to replace that with a named entity recognition model that reads the sentence instead of just scanning for a shape.

Building the pipeline

30+ crawlers feeding a MySQL table — source, title, URL, publisher, and both published and collected timestamps
BIO tagging scheme — B-LOC/I-LOC spans marking a multi-word location entity
Domain dictionary built from scratch across 8 entity categories, used to bootstrap BIO labeling

Results

Micro avg F1: 67% → 91% Macro avg F1: 56% → 80% Weighted avg F1: 65% → 91%
Per-entity precision/recall/F1, before (left) and after (right) cleaning mislabeled training data

The biggest single jump came from classes that were badly mislabeled early on. MALWARE went from an F1 of 0.18 to 0.88 and IP from 0.20 to 0.72 once the training labels were actually correct, a bigger gain than any change to the model itself produced.

Takeaways

Good text preprocessing moves the needle more than model tuning
Cleaning up the text and fixing mislabeled training data drove most of the F1 gain, more than any architecture or hyperparameter change did.
Labeling is the real time sink, not modeling
Manually annotating BIO tags across 50,000+ articles took far longer than training or tuning the model ever did.
Design crawlers for continuous updates, not a one-time pull
Building for a single scrape is the easy path, but a crawler that can't cleanly re-run to pick up only newly published articles turns into throwaway code fast.
A visible countdown timer keeps meetings from running long
Borrowed the practice from how Google reportedly runs meetings: put a shared timer on screen with a hard limit, and meetings stop drifting.
Meeting notes need an owner and a status, not just a summary
Every to-do due before the next meeting needs a named owner and a trackable done/not-done state, or it quietly doesn't get done.
