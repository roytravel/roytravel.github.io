Real and Fake Face Detection

Pattern Recognition (Graduate) · Korea University · Jun 2021
Each file is labeled with a 4-bit code marking which of 4 regions (left eye, right eye, nose, mouth) was manipulated

Overview

An assignment from a graduate Pattern Recognition course at Korea University, offered as one of three topic choices. I picked manipulated-face detection: given a face photo, decide whether it's been digitally altered, and if so, which facial region was touched. No pretrained backbone was allowed, so both models were trained from scratch.

I built two separate CNNs rather than one multi-task model: a binary classifier that flags whether an image is real or manipulated, and a second model that predicts which of four regions (left eye, right eye, nose, mouth) were altered, output as a 15-way classification over every non-empty combination of the four regions. The dataset wasn't GAN-generated, it was Photoshop-manipulated, which shaped which prior work was actually relevant and which model design to use.

What a manipulated face looks like

Easy difficulty — manipulation is subtle even at close inspection
Mid difficulty — visually convincing, hard to flag by eye alone

The dataset spans easy, mid, and hard difficulty tiers. Even at mid difficulty, the edits are clean enough that manual review isn't reliable, which is the actual case for automated detection.

Related work

"Detecting Photoshopped Faces by Scripting Photoshop" — Wang et al., ICCV 2019, found via Papers with Code

Most SOTA manipulation-detection work targets GAN-generated forgeries. This dataset wasn't GAN-based, so that line of research didn't apply. The Photoshop-scripting paper was a closer match: its dataset was also built from ordinary tools like Adobe Photoshop rather than a generative model, and its two-model split (a global real/fake classifier plus a local region classifier) is exactly the structure I used.

Dataset

4,080 images total 2,040 train / 2,040 test 959 manipulated / 1,081 real per split

Manually reviewing the labeled set turned up one image whose filename claimed a manipulation that wasn't actually visible or verifiable. I excluded it rather than trust the label blindly.

Image augmentation

The dataset wasn't large enough to train reliably without augmentation, confirmed by first running both models with none. The two models needed different settings, not the same recipe copy-pasted twice, because they answer different questions about the same faces.

Building the label set

Parsed the 4-digit code out of each filename into a structured dataframe for the localization model

My first attempt treated left_eye, right_eye, nose, and mouth as four separate binary targets. It trained poorly. Collapsing them into one combined categorical label (the label column above, one of 15 classes) instead of four independent outputs fixed it. Framing the four correlated sub-decisions as a single classification target gave the model a much cleaner signal to learn from.

Takeaways

Collapse correlated sub-labels into one target instead of predicting them independently
Four separate binary heads for four correlated regions trained poorly. One combined 15-way label over the same information trained cleanly.
Don't trust dataset labels blindly, spot-check them
Manually reviewing the labeled images surfaced one filename whose claimed manipulation wasn't actually verifiable. Excluded it rather than train on a bad label.
Augmentation choices should follow the task's semantics, not a default checklist
Horizontal flip is a standard augmentation, but it would have silently swapped the left-eye/right-eye ground truth for the localization model. Skipped it there, kept it for the real/fake classifier where it didn't matter.
Match the reference paper to the actual data generation process, not just the task name
Most manipulation-detection SOTA targets GAN forgeries. This dataset was Photoshop-edited, so a Photoshop-scripting detection paper was the more relevant prior work, even though it's less cited than GAN-detection papers.
Textbook layer ordering isn't always the best fit empirically
CS231n's recommended Conv2D → BatchNorm → MaxPool ordering underperformed Conv2D → MaxPool → BatchNorm on this task. Tested both instead of assuming the textbook order would win.
