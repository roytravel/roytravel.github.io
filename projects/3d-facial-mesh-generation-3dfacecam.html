Korean Face 3D Mesh Expression Validation Model

Ellexi · Jul 2023 – Feb 2024 · 8 months
System pipeline — sentence classification (BERT) + mesh generation (3DFaceCAM), Training and Inference phases
3DFaceCAM architecture — Step I: Stacked Autoencoder (SAE) for identity/expression disentanglement; Step II: cGAN for mesh and texture generation

Overview

A third-party organization built a Korean face 3D mesh dataset covering 2,500 subjects with 51 expression variations each — 127,500 meshes in total — for public release on AI-HUB. Ellexi's role was to validate whether that dataset was actually usable: build a model that generates 3D facial meshes from emotional context, and certify it through an official TTA reproducibility audit.

The validation model takes a Korean sentence describing a social situation, classifies the implied emotion with BERT, and generates the matching 3D facial mesh using 3DFaceCAM — a two-stage architecture combining a Stacked Autoencoder for identity/expression disentanglement with a cGAN for mesh and texture synthesis. A key constraint: the dataset had been built with camera calibration rather than laser scanning, which meant vertex correspondence across subjects was not guaranteed. To work around this, the model had to be trained per subject. I wrote the R&D proposal that won the project, ran training on 4× A100 80GB GPUs, and built the Docker evaluation pipeline used for official TTA certification — hitting Diversity ≥ 1.3 and Specificity ≤ 0.90.

Takeaways

Camera-calibration meshes break vertex correspondence, which breaks GAN training
The dataset was built by another company using camera calibration rather than laser scanning. Camera-calibration meshes don't share vertex topology across subjects, so there's no consistent correspondence for the model to learn from. The only workaround was training a separate model per subject — 2,500 subjects, 51 expressions each. Laser-scanned meshes solve this by construction.
GAN loss curves don't tell you if training is working
Generator and discriminator losses can look stable while the model is producing garbage. The only way to know is to inspect intermediate outputs throughout training.
Read open-source code critically — even from large organizations
Meta's published implementation had logic errors. Assuming that widely-cited code is correct is a fast way to lose weeks of debugging time.
Papers rarely release everything — plan to implement the gaps yourself
Key components are often missing from public repositories. Treat any research implementation as incomplete until you've verified each piece exists and works.
